# T11 — API contract evals скрипт

**Blocked by:** T04

## Мета

Wire-контракт перевіряється end-to-end на живому API, а не лише на рівні серіалізації.

## Що робить (vertical slice)

1. JSON-схеми endpoint'ів у docs/ (очікуваний контракт, camelCase — ADR-0001).
2. scripts/api-eval.ps1:
   - піднімає API локально (http://localhost:5254)
   - обхід основних endpoint'ів, валідація відповідей проти схем
   - читабельний звіт: endpoint → ok/mismatch → різниця
3. Запуск локально; увімкнення в CI (в job `evals`, T07) — окремим рішенням, якщо
   виявиться стабільним.

## Verifiable outcome

- Навмисна зміна структури відповіді контролера падає в звіті з вказівкою поля.

## Acceptance criteria

- [ ] Схеми покривають основні endpoint'и (не обов'язково всі — перелік в описі PR)
- [ ] Скрипт не мутить стан API (тільки читання)
- [ ] Працює на чистому репо без ручних кроків крім запуску
- [ ] Повідомлення помилок вказують конкретну відмінність від схеми

## Out of scope

- Написання нових endpoint'ів
- Зміна контракту (тільки через ADR-0001)
- Зовнішні валідатори-сервіси
