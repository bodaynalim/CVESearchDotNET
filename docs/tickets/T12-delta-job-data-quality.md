# T12 — Data-quality інваріанти delta jobs

**Blocked by:** — (стартує одразу)

## Мета

Delta jobs (MongoDB) перевіряються інваріантами на фікстурах — без використання
живого Mongo state як fixture (AGENTS.md §2).

## Що робить (vertical slice)

1. Фікстури виходу delta jobs (вхідний batch → очікуваний результат).
2. Тести інваріантів:
   - id не порожні, унікальні в межах batch
   - дедупікація працює як задумано
   - дати модифікації монотонні (не "в минуле")
   - розмір дельт у межах очікувань (вихлоп/пустота — помилка, не тиха ok)
3. Якщо логіка джобів чиста — тестувати її як pure function; якщо ні — через
   наявний інтеграційний шов.

## Verifiable outcome

- Навмисне порушення інваріанту (наприклад, дублікати id) падає з назвою інваріанту.

## Acceptance criteria

- [ ] Кожен інваріант має і позитивний, і негативний кейс
- [ ] Тести не піднімають живу MongoDB (якщо потрібен Mongo — testcontainer/наявний
      підхід, не dev-БД)
- [ ] Нові терміни (якщо з'являться) — в GLOSSARY.md
