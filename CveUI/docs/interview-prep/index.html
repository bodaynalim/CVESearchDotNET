How to use this guide

Each page is one study theme group. Start with Architecture core: it establishes the state topology and the two patterns (resource idling, the page clamp) that every later theme assumes. The Decisions & testing page is your differentiator material; the Implementation craft page covers the remaining code-grounded themes; Synthesis closes with the cross-cutting full-stack answers and the three-minute opening narrative.

The system in one paragraph

CveUI is the read-only Angular SPA that browses the CVE Search API. It holds no server-side state and treats URLs as the browsable source of truth for list state: refresh, back/forward, and deep links all restore state because only the URL carries it. State is split by ownership — the URL owns all listing state, signals own derived and ephemeral state, and the browser's localStorage owns Recent lookups. There is no global store; the URL is the store for anything shareable.

Glossary — use these words

In the interview, use the project's own vocabulary so your phrasing matches the code and docs: Vulnerabilities page (the default CVE list view), CVE lookup (opening a single CVE by exact ID), Global CVE search (the same list page, unscoped), Weaknesses page (the CWE list), Vendors & Products (drill-down navigation), Keyword (a single submitted search phrase — never "live search"), Result set (one count request serves all page turns of the same match), Severity badge (the color-classified CVSS chip), Recent lookups and the Recent lookup chip.
