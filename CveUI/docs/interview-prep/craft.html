Pure business logic, router and composition patterns, and the Tailwind token system — the remaining code-grounded themes.

Theme: CVSS severity mapping — business logic as pure functions

What to say
"The severity chain — string from the API, then score thresholds, then 'Not scored' — lives in pure exported functions with their own specs. No framework involved, trivially testable. Where logic is pure, it gets a direct test regardless of the integration-first testing stance for behavior."

What the code does

src/app/core/severity.ts:

  • severityFromCvss3 — thresholds validated against the backend's NVD-imported severity strings: None ≤ 0, Low < 4, Medium < 7, High < 9, Critical ≥ 9.
  • severityFromCvss2 — same scale but no Critical tier: High starts at ≥ 7.
  • canonicalSeverity("HIGH") → "High"; unknown, empty, or missing → null.
  • resolveCvssSeverity — prefers the API's severity string; falls back to the threshold function when the string is missing but the score is present.

The Vulnerabilities page (and CVE detail) renders the Severity badge with the v2-or-v3 preference and, when neither CVSS block has a score, a neutral "Not scored" chip — the end of the fallback chain, never an error.

Likely probe

"Where do the threshold rules live?" — In one pure module, documented against the backend's string conventions, with severityBadgeClass as the only place that maps a severity name to a color token — "which red is Critical" is a one-line change.

Theme: Router & composition patterns

What to say
"Standalone everything, inline templates where colocation helps, built-in control flow, and query-param-to-input() binding — the router hands the page its state, and the page never reads the router object directly to get it."

Patterns to name and demonstrate

  • Standalone components with inline templates (the Vulnerabilities page) — one file colocates template, parse functions, and component; larger pages and the shell use separate template files. Colocation is a per-page judgment, not doctrine.
  • Built-in control flow: @if (expr; as alias) for unwrapping without null-juggling in the template; @for with identity-based track cve.cveId — never index tracking, CVE IDs are the natural key.
  • URL → inputs: withComponentInputBinding() (+ path params for the vendor/product routes) means the page is a pure function of its URL; no ActivatedRoute.snapshot spelunking.
  • Interop at the boundary: the app shell turns router events into a section-title signal with toSignal(router.events.pipe(filter, map, startWith)) (src/app/app.ts). RxJS lives at event streams; signals live inside components — a stated split, not an accident.
  • Guards against drift: URL values are parsed through whitelist functions before they reach the API layer — the page never forwards a raw count or unknown sort downstream.

Likely probe

"Why inline templates for the list page?" — Its rendering branches (loading / not-found / error / rows / pager) are one narrative unit; splitting them into five files makes reviewing the state machine harder than writing it inline. Craft, not fashion.

Theme: Tailwind 4 @theme design tokens

What to say
"The design language is light content area plus a dark indigo sidebar. Tokens are declared once in @theme — CSS variables, no Tailwind config file — and consumed as utilities or var() references anywhere."

What the code does

src/styles.css declares the palette:

@theme {
  --color-nav-bg: #191934;          /* dark indigo sidebar */
  --color-brand: #5c53e0;
  --color-page-bg: #eef0f4;
  --color-card-border: #e3e4ea;
  --color-panel-accent: #33306b;
  --color-severity-low: #00b8d9;    /* + medium / high / critical / none */
}

Consumption is uniform:

  • Arbitrary values in templates — bg-[var(--color-brand)], border-[var(--color-card-border)], hover:border-[var(--color-brand)] — so markup references tokens, not hex.
  • The one name→color mapping — severityBadgeClass() in src/app/core/severity.ts maps each severity to its token class, keeping palette changes single-point.
  • Base typography via @apply — html { @apply text-slate-800 antialiased; } — design utilities over raw CSS in globals.

Likely probe

"Why @theme over a config file?" — Tailwind 4 is CSS-first: the tokens are the CSS variables themselves and can be scoped or changed without a build-config indirection; utilities derive from the same source of truth the components read.
